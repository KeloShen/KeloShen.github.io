## thesis: 一本毕业论文 | 论文, 毕设, 毕业论文, llm-txinsight
本科毕业论文 ·《基于大模型的定制化银行客户交易记录合理性分析系统设计与实现》
系统名称：LLM-TxInsight · 与汇丰科技合作 · 2025.12 – 2026.04

要解决的问题
银行合规审查中，分析人员要人工核对客户信息和交易流水。流程繁琐、效率不高，不同审核人员的判断标准不统一，遇到模糊的交易也很难给出清晰、可解释的结论。

我做了什么
一个前后端分离的 B/S 系统（Spring Boot 3 + LangChain4j、Vue 3、PostgreSQL）。上传客户信息和交易文件（Excel/CSV），系统输出三段式报告（客户概述、交易摘要、合理性陈述），可以导出为 Word。
  · 分阶段分析，而不是一个大 Prompt：阶段一筛查明显不合理的模式（大额异常、快进快出、多人归集）；阶段二结合客户的职业和收入判断合理性；证据不足时进入阶段三，向分析人员生成有针对性的追问（最多 3 轮）。
  · 场景 Skill：亲友间转账、结构性存款、高风险国家等规则只在需要时加载；高风险国家名单从数据库查询，不写死在提示词里。
  · 复核智能体对每个结论进行复查；如果和分析智能体的意见不一致，就转入人工仲裁，并保存仲裁记录。
  · 分析人员的反馈会被提炼成可复用的经验，供之后的分析引用。
  · 后端 171 个测试方法（JUnit 5、Mockito，含单元测试和集成测试），前端组件测试（Vitest）。

测试评估 · 500 条标注用例（约 200 条合理、200 条不合理、100 条需人工）
  · Qwen-plus：原始 Prompt 50.0% → Few-shot + 思维链 60.4% → 分阶段编排 68.0%
  · 最佳结果：Qwen3.6-max-preview 启用 Skill 后达到 86.7%；Qwen3-max 启用 Skill 后为 83.1%，超过任务书要求的 80%
  · 按需加载 Skill 让各模型的 Token 消耗下降约 20%–30%
  · 最便宜的模型（DeepSeek V4 Flash，每个用例约 0.03 元）准确率只有 57.6%：选模型就是在准确率和成本之间做权衡

主要结论
把任务拆成目标单一的阶段，比各种提示词技巧更能提升准确率；上下文规模是可以通过设计来控制的成本；一个知道什么时候该问人的系统，比一个永远都给答案的系统更值得信任。

## agent: 合规智能体 | 智能体, 银行, 汇丰, 反洗钱, 毕设项目, 原型a
项目 · 银行客户交易记录合理性分析系统
与汇丰科技合作 · 2025.12 – 2026.04 · 本科毕业设计
做什么：面向银行反洗钱与合规审查的智能分析系统。输入客户基本信息和交易流水，由大模型智能体判定每笔交易是否合理，给出结论、理由和证据；无法确定的高风险案例自动转人工复核。
我做了什么：
  · 独立设计并实现基于 LangChain4j + Spring Boot 3 的后端架构，持久化多轮对话记忆，支持同一任务内的追问
  · 多智能体编排流水线：检测 → 复审 → 需人工澄清 → 终局裁决，低置信度自动转人工（Human-in-the-Loop）
  · 可插拔的 Skill 库：每条检测规则封装为独立 Skill（规则 + 参数 + 参考知识），通过"规则预选 + 语义匹配"按需加载，实现渐进式披露和 RAG 式检索
  · Function Calling：由模型自主决定激活哪些 Skill，而不是一次性注入全部内容
  · 用户反馈闭环：纠错信息自动提炼成经验并沉淀，后续分析动态引用，实现智能体自学习
  · 分层思维链（CoT）+ 反幻觉约束的提示词工程，版本化迭代以提升准确率
  · 前端使用 Vue 3 + TypeScript + Tailwind CSS 4
